# Инфраструктура AWS

> Каноническая инструкция проверяющему находится в
> [`docs/reproduction.md`](../docs/reproduction.md). Ниже приведён краткий
> справочник по Terraform-модулям.

Terraform разделён на три отдельных root-модуля с собственными state:

| Каталог | Назначение | Время жизни |
|---|---|---|
| `bootstrap` | boundary, права разработчика и запрос квоты | однократно для авторского аккаунта |
| `billing-guard` | бюджет, уведомления и аварийная остановка помеченных EC2 | постоянный контур авторского аккаунта |
| `runner` | сеть, четыре измерительных узла, NAT, S3, SSM и TTL | один временный стенд |

Готовый runner использует созданную bootstrap-модулем boundary и фиксированные
имена `spectral-*`, поэтому один аккаунт и регион обслуживаются одним
оркестратором из одной рабочей копии.

## 1. IAM bootstrap

[`bootstrap/README.md`](bootstrap/README.md) описывает IAM-контур, в котором
разрабатывалось решение. Значения по умолчанию привязаны к конкретным account ID,
IAM user и `us-east-1`; модуль документирует минимальные права авторского
аккаунта. Проверяющий может адаптировать его параметры и имена либо выдать
эквивалентные права своей принятой IAM-схемой.

Модуль также запрашивает квоту 34 Standard On-Demand vCPU. Самому стенду нужны
18 vCPU: 16 для четырёх `m8a.xlarge` и 2 для NAT `t4g.nano`.

## 2. Контроль расходов

Каталог `billing-guard` создаёт месячный бюджет 10 USD по расходу до применения
credits и refunds. Уведомления настроены на фактические 50%, 80%, 100% и прогноз
100%. При фактических 100% Lambda останавливает EC2 только при совпадении тегов:

```text
Project  = spectral-task
AutoStop = true
```

Обновление AWS Budgets может запаздывать. Основную защиту короткого стенда дают
общий абсолютный TTL, локальные shutdown-таймеры и EventBridge Scheduler; бюджет
служит дополнительным аварийным контуром.

Настройка этого постоянного контура выполняется отдельно от runner:

```bash
cd infra/billing-guard
cp terraform.tfvars.example terraform.tfvars
# Укажите alert_email или оставьте пустую строку.
terraform init
terraform plan
terraform apply
```

## 3. Временный runner

Каталог `runner` создаёт:

- один узел-источник и три узла-получателя `m8a.xlarge`;
- одну приватную подсеть в дочерней `cluster` placement group внутри
  `precision-time`;
- управляющий ENI под Linux и отдельный измерительный ENI под DPDK на каждом
  узле;
- доступ через SSM без публичных IPv4 и входящих портов управления;
- временный NAT `t4g.nano` для исходящей подготовки;
- приватный S3 bucket с точным `.deb` и результатами;
- зашифрованные gp3-диски, IMDSv2, Scheduler и локальные TTL-таймеры.

Приложение собирается и проверяется на рабочей станции командой `make deb`, после
чего Terraform доставляет пакет на EC2 через S3. Подготовка узла устанавливает
закреплённое AWS-ядро, `chrony`, системные DPDK/DKMS-пакеты и собирает официальный
ENA 2.17.2. `gcc`, `git` и `make` на узле обслуживают только ENA/DKMS; CMake и
nFPM используются в сборочном контейнере приложения.

Жизненный цикл требует поэтапной оркестрации: регистрация новых EC2 в SSM,
установка пакета, reboot, проверка PHC/DPDK и включение общего TTL происходят
последовательно. Публичной точкой входа служат Make-цели:

```bash
make aws-cluster-up
make aws-cluster-status
make aws-cluster-phc-verify
make aws-cluster-dpdk-verify
```

Параметры сдаваемого DPDK-запуска и полный набор команд приведены в
[`docs/reproduction.md`](../docs/reproduction.md#7-наш-автоматизированный-путь).
Изменения runner выполняются Make-целями, которые реализуют многофазный протокол
готовности. Для чтения состояния отдельно доступны `terraform plan`,
`terraform output` и `terraform state`.

Между короткими сессиями стенд можно остановить с сохранением EBS и state:

```bash
make aws-cluster-stop
make aws-cluster-start
```

Перед полным удалением результаты скачиваются локально. `down` удаляет временный
S3 bucket вместе с содержимым и завершает встроенной проверкой отсутствия
проектных ресурсов:

```bash
make aws-cluster-fetch
make aws-cluster-down
```

Подробная топология, CPU pinning и устройство сборки описаны в
[`docs/aws-runner-topology-and-build.md`](../docs/aws-runner-topology-and-build.md).
