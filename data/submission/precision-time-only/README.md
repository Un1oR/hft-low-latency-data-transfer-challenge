# Производные данные эпохи `precision-time only`

Этот каталог содержит отдельный воспроизводимый срез без дочерней `cluster`
placement group. Источник - единая EC2-эпоха
`submission-suite-20260829T161712Z` и её сравнительная матрица
`comparison-20260829T161715Z` на четырёх `m8a.xlarge` в одной
`precision-time` placement group.

Сравнительная часть содержит только `N=3`: по шесть контрсбалансированных
блоков `Claude ↔ DPDK` при `200 тыс.` и `2 млн событий/с`. Все 24 зачтённых
плеча используют одинаковый двухсекундный прогрев, по миллиону измеряемых
событий на получателя, одни instance IDs и SHA пакета, ENA PHC, нулевую поправку
часов и полную доставку. В итоговый набор входят 24 валидированных плеча.

Формат файлов совпадает с родительским каталогом `data/submission`. Поэтому для
этой эпохи тем же кодом рассчитываются доставка всем по совмещённым `seq_id`,
три кривые получателей, равновзвешенное распределение получателя, среднее трёх
задержек события, парные эффекты, плотности, временные всплески и нагрузочные
срезы. Парного Claude-сравнения для `N=1` в этой эпохе нет. Аппаратные
RX-интервалы и раскладка тракта в отчёте не используются.

Наблюдаемая абсолютная задержка порядка `100–130 мкс` характеризует совокупные
условия этой эпохи: физическое размещение и остаточный сдвиг межхостовых часов.
Сравнительные выводы рассчитываются внутри эпохи; `cluster`-эпоха показана в
отчёте отдельным срезом.

Пересборка из локальных сырых артефактов:

```bash
uv run --frozen python scripts/build-submission-data.py \
  --suite artifacts/aws-runner/submission-suite-20260829T161712Z/suite.json \
  --epoch-profile precision-time-only \
  --output data/submission/precision-time-only
```

Точные manifests, правила агрегации и описание placement лежат в
`provenance.json`. Исходные CSV по событиям остаются в игнорируемом каталоге
`artifacts/aws-runner/`.
