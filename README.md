# Low-latency data transfer

> [!NOTE]
> 🏆 **9-е место из 100+ финальных работ**
>
> Конкурсная реализация для
> [Low-latency Data Transfer Challenge](https://t.me/SpectralTech/591)
> от Spectral::Technologies.
>
> Оригинальная постановка задачи: [русская версия](TASK.md) ·
> [English version](TASK_en.md)

Реализация рассылает поток с одного узла-источника на `1..3`
отдельных узла-получателя через DPDK и ENA. `producer` строит рыночное событие
прямо в слоте SPSC-очереди, а `sender` читает этот слот без промежуточной копии,
кодирует компактное самодостаточное представление и отправляет отдельный
Ethernet/IP/UDP-пакет каждому адресату. На принимающей стороне `receiver`
проверяет дейтаграмму и декодирует событие прямо в выходную SPSC-очередь для
`consumer`; исходные `seq_id` и `send_ts_ns` сохраняются по всему тракту.

Формат уменьшает исходные `Trade/BBO/OrderBook` с `192/192/576 Б` до объектов
`80/64/160 Б`; сетевой кодек передаёт их в `76/60/150 Б`. Пачка остаётся в
пределах MTU и самодостаточна после потери отдельного UDP-пакета. Цель пачки
зависит от частоты событий и числа получателей: это снижает число сетевых пакетов
около ограничения ENA, а максимальное дополнительное ожидание ограничено
`1200 нс`. Материалы решения:

- [`analysis.ipynb`](analysis.ipynb) — русскоязычный отчёт с совмещёнными
  распределениями нашего решения и baseline, нагрузочными срезами и выводами;
- [`docs/reproduction.md`](docs/reproduction.md) — конфигурация AWS-стенда,
  сборка, запуск, проверка измерений и переносимый ручной эквивалент;
- [`docs/aws-runner-topology-and-build.md`](docs/aws-runner-topology-and-build.md)
  — устройство автоматизированного стенда и жизненный цикл инфраструктуры;
- [`data/submission/README.md`](data/submission/README.md) — состав компактного
  набора измерений, происхождение данных и правила агрегации.
